# Cockpit Anchor — repo guide for AI agents & contributors

Cockpit Anchor makes **Assetto Corsa**'s VR cockpit load in the **same physical seat every session** on a
**Meta Quest 3 over Virtual Desktop**, with **no manual recentering** — and auto-fixes a Virtual-Desktop
launch black screen. Two components ship together. User-facing setup is in [`README.md`](README.md);
this file is for working *on* the code.

## What's in this repo

| Path | What |
|---|---|
| `api-layer/src/layer.cpp` | The **OpenXR API layer** (one C++ file). Re-bases the seat for any *enabled* game; the black-screen auto-bounce stays AC-only. Inert in non-enabled apps. |
| `api-layer/build.ps1`, `install.ps1`, `uninstall.ps1`, `CockpitAnchor.json` | Build the DLL; register/unregister it as an implicit OpenXR layer (HKLM). |
| `ui/` | The **Electron control panel** (manage games, status, install/uninstall, auto-update). |
| `.github/workflows/build.yml` | CI: on tag `v*`, build the DLL + the NSIS installer, draft a GitHub release. |
| `RELEASE_NOTES.md` | Body for the next release (CI reads it). |

## The pipeline (why it's shaped like this)
`AC (OpenVR) → OpenComposite (openvr_api.dll → OpenXR) → [this layer] → VDXR → Virtual Desktop → Quest 3`.
AC is OpenVR-only, so OpenComposite bridges it to OpenXR; our layer is an OpenXR API layer that sits
between OpenComposite and VDXR. (iRacing is native OpenXR → no OpenComposite needed.)

## How it works (one paragraph each)
- **Anchor:** the layer intercepts `xrCreateReferenceSpace`. When AC asks for its `LOCAL` (seated) space and
  a saved anchor exists, the layer instead returns a `STAGE` (room-fixed) space pinned to the anchor pose,
  so AC's "seat" becomes a fixed real-world point. Calibrate with `Ctrl+Shift+S` (capture seat-in-STAGE →
  save), unlock to reposition with `Ctrl+Shift+B`. Requires VD **stage tracking ON** (room-fixed STAGE).
- **Black-screen auto-bounce:** the launch black screen is a VD compositor issue (app/OC/layer all submit
  valid frames; VD just doesn't scan out). The layer reproduces the manual fix — ~1.5s after the session is
  FOCUSED it `SendInput`s VD's "Toggle VR Mode" hotkey (default `Shift+Win+D`) twice, out to the VD
  environment and back, re-arming VD. The chord is configurable via `bounce-key.txt` (the app writes it from
  VD's `BindingSettings.json` if the user remapped the key).

## GUI ↔ layer contract (`%LOCALAPPDATA%\CockpitAnchor\`)
The app owns rich state and derives the simple files the layer reads (the layer never parses JSON for the
game list):
- `games.json` (app) → derives `enabled-games.txt` (one enabled exe per line; layer reads; absent ⇒ `acs.exe`).
- `anchor-mode.txt` (app → layer) — `shared` (default) or `unique`. Shared ⇒ every game uses `seat-anchor.json`; unique ⇒ per-game `seat-anchor-<stem>.json`.
- `seat-anchor.json` (shared) / `seat-anchor-<stem>.json` (per-game) (layer ↔ layer) — the saved pose.
- `bounce-key.txt` (app → layer) — optional VD keybind override (decimal VK codes); absent ⇒ `Shift+Win+D`.
- `cockpit-anchor.log` (layer) — diagnostics.

## Build / run / release
- **Layer:** `git clone --depth 1 https://github.com/KhronosGroup/OpenXR-SDK deps/OpenXR-SDK` once, then
  `powershell -ExecutionPolicy Bypass -File api-layer/build.ps1` → `api-layer/build/CockpitAnchorLayer.dll`.
  The registered manifest points there, so a rebuild is live next AC launch (**close AC first** to overwrite).
- **UI:** `cd ui && npm install`, then `npm start` (dev) or `npm run dist` (NSIS installer →
  `ui/dist/CockpitAnchor-Setup.exe`; needs the layer DLL built first — it's bundled via `extraResources`).
- **Release:** bump `ui/package.json` version to `X.Y.Z` (must equal the tag), update `RELEASE_NOTES.md`,
  then `git tag vX.Y.Z && git push origin main && git push origin vX.Y.Z`. CI drafts a release with the
  installer (`CockpitAnchor-Setup.exe` only); publish it with `gh release edit vX.Y.Z --draft=false --latest`. The in-app updater then
  offers it to existing users (it matches the published asset named `…Setup.exe` and compares versions).

## Conventions / gotchas
- Windows + PowerShell. Git-Bash mangles MSVC `/flags` into paths — run `cl`/`dumpbin`/`lib` from PowerShell.
- `.gitignore` excludes build output (`api-layer/build/`, `*.dll`, `ui/dist`, `ui/node_modules`), `deps/`,
  `*.bak`. CI builds from source.
- The app **icon** is generated by code (`ui/scripts/gen-icon.js` rasterizes the anchor) — don't paste base64.
- The auto-bounce fires on **every** launch (the app can't tell good launches from bad), so a brief
  VR→VD→VR flip on load is expected.
- The installer is **unsigned** (SmartScreen warns). Multi-sim support is scaffolded but only **`acs.exe`
  (Assetto Corsa)** is tested/supported; other sims show "coming soon" in the UI.
